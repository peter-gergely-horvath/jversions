Java 11 covers 9–11

Mostly a migration hurdle (modules, encapsulation) with few language gains.

  • Langvar for locals10

    Local variables only. Still static typing; the type is inferred. var list = new ArrayList<>() infers ArrayList<Object>.

    var users = new ArrayList<User>();
BiFunction<Integer,Integer,Integer> add = (var a, var b) -> a + b; // 11

    JEP 286: Local-Variable Type Inference
    JEP 323: Local-Variable Syntax for Lambda Parameters

  • JVMModule system (JPMS)9

    Most apps stay on the classpath. The real impact: JDK internals are encapsulated. In 11 reflective access only warns; 17 makes it an error.

    module com.example.app {
    requires java.sql;
    exports com.example.app.api;
    opens com.example.app.model to com.fasterxml.jackson.databind;
}

    JEP 261: Module System
    JEP 260: Encapsulate Most Internal APIs

  • JVMG1 default, ZGC and Epsilon (experimental)9–11

    G1 is the default GC. ZGC targets very low pauses on large heaps; Epsilon never reclaims memory (benchmarks, short jobs).

    java -XX:+UseParallelGC -jar app.jar     # go back to Parallel
java -XX:+UnlockExperimentalVMOptions -XX:+UseZGC -jar app.jar

    JEP 248: Make G1 the Default Garbage Collector
    JEP 333: ZGC: A Scalable Low-Latency Garbage Collector (Experimental)
    JEP 318: Epsilon: A No-Op Garbage Collector (Experimental)

  • JVMContainer awareness10

    The JVM respects cgroup CPU and memory limits (backported to 8u191). Prefer percentages over hardcoded -Xmx.

    java -XX:MaxRAMPercentage=75 -jar app.jar
  • JVMJava Flight Recorder open-sourced11

    Low-overhead production profiling, built in. Open the file in JDK Mission Control.

    java -XX:StartFlightRecording=duration=60s,filename=rec.jfr -jar app.jar
jcmd <pid> JFR.dump name=adhoc filename=rec.jfr

    JEP 328: Flight Recorder

  • JVMSingle-file launch11

    Run a source file without an explicit javac step. Works as a script with a shebang.

    java Hello.java arg1 arg2

    JEP 330: Launch Single-File Source-Code Programs

  • JVMTLS 1.311

    Enabled by default (backported to 8u261). Escape hatch for old middleboxes:

    -Djdk.tls.client.protocols=TLSv1.2

    JEP 332: Transport Layer Security (TLS) 1.3

  • JVMCollector overview: Serial, Parallel, G1, ZGC, Epsilon9–11

    Serial: tiny heaps, single CPU. Parallel: max throughput for batch jobs. G1: balanced default. ZGC: low latency, experimental in 11. Epsilon: no-op. The JVM silently falls back to Serial when it sees under 2 CPUs or about 1.8 GB RAM, which often surprises people in small containers. This ends in Java 27 (see Java 29).

    -XX:+UseSerialGC   -XX:+UseParallelGC   -XX:+UseG1GC
  • JVMUnified logging (-Xlog)9

    One logging framework for all JVM subsystems; replaces the old -XX:+PrintGC* flags.

    java -Xlog:gc*:file=gc.log:time,uptime,level,tags -jar app.jar

    JEP 158: Unified JVM Logging
    JEP 271: Unified GC Logging

  • JVMCompact strings9

    Latin-1 strings are stored as one byte per char instead of two. Automatic, often a noticeable heap saving on string-heavy apps.

    JEP 254: Compact Strings

  • JVMjshell REPL9

    Interactive shell for trying out code and APIs without a project.

    JEP 222: jshell: The Java Shell (Read-Eval-Print Loop)

  • JVMMulti-release JARs9

    One JAR can ship version-specific classes under META-INF/versions/N.

    JEP 238: Multi-Release JAR Files

  • JVMjlink runtime images9

    Builds a trimmed runtime image; use jdeps --print-module-deps to find the modules.

    jlink --add-modules java.base,java.sql --output runtime

    JEP 282: jlink: The Java Linker

  • LibStandard HttpClient (HTTP/2)11

    Replaces HttpURLConnection for most uses. Immutable, reusable, supports async and WebSocket.

    var client = HttpClient.newHttpClient();
var req = HttpRequest.newBuilder(URI.create("https://api.example.com")).GET().build();
var resp = client.send(req, BodyHandlers.ofString());
client.sendAsync(req, BodyHandlers.ofString()).thenApply(HttpResponse::body);

    JEP 321: HTTP Client API

  • LibImmutable collection factories9–11
    List.of(1, 2);       // immutable list
Set.of("a");         // immutable set
Map.of("k", 1);      // immutable map

    JEP 269: Convenience Factory Methods for Collections

  • LibOptional additions9–11

    Optional got better handling of the empty case in 9 and 11.

    opt.ifPresentOrElse(use, orElse);   // 9: run an action, or a fallback
opt.or(() -> alt);                  // 9: fall back to another Optional
opt.isEmpty();                      // 11: the opposite of isPresent()

    No JEP for this one, see the Javadoc: Optional (Java 11)

  • LibStream takeWhile / dropWhile9

    Short-circuiting operations that work on the prefix of an ordered stream.

    stream.takeWhile(x -> x < 10);   // keep elements until the predicate first fails
stream.dropWhile(x -> x < 10);   // skip elements until the predicate first fails

    No JEP for this one, see the Javadoc: Stream (Java 11)

  • LibProcess API (ProcessHandle)9
    ProcessHandle.current().pid();                      // process API

    JEP 102: Process API Updates

  • LibFlow (reactive-streams interfaces)9

    Publisher, Subscriber, Subscription and Processor in java.util.concurrent.Flow; a common base for reactive libraries.

    JEP 266: More Concurrency Updates

  • DeprecatedCMS garbage collector9

    Deprecated in 9; removed in 14.

    JEP 291: Deprecate the Concurrent Mark Sweep (CMS) Garbage Collector

  • DeprecatedNashorn JavaScript engine11

    Deprecated in 11, removed in 15. Use GraalJS or another engine if you embed JavaScript.

    JEP 335: Deprecate the Nashorn JavaScript Engine for Removal

  • DeprecatedPack20011

    Deprecated in 11; removed in 14.

    JEP 336: Deprecate the Pack200 Tools and API

  • DeprecatedApplet API9

    Deprecated in 9 as browsers dropped plugin support; deprecated for removal in 17.

    JEP 289: Deprecate the Applet API

  • RemovedJava EE and CORBA modules removed11

    JAXB, JAX-WS, javax.activation, javax.annotation and CORBA are gone from the JDK. Add them as Maven/Gradle dependencies (Jakarta artifacts). A classic 8→11 compile error.

    JEP 320: Remove the Java EE and CORBA Modules

  • RemovedJavaFX no longer bundled11

    JavaFX left the JDK in 11 and lives on as the separate OpenJFX project.

  • RemovedJava Web Start11

    Java Web Start (javaws) was removed in 11.

Java 17 covers 12–17

The big language jump: records, sealed types, switch expressions, text blocks.

  • LangRecords16

    Shallowly immutable data carriers with generated equals, hashCode, toString. Not JPA entities; Jackson needs 2.12+.

    public record Point(int x, int y) {
    public Point {                       // compact constructor
        if (x < 0 || y < 0) throw new IllegalArgumentException();
    }
}
new Point(1, 2).x();                     // accessor, no "get"

    JEP 395: Records

  • LangSealed classes17

    Closed hierarchies the compiler knows completely. With records, this is Java's algebraic data types; pays off with pattern switch in 21.

    public sealed interface Shape permits Circle, Rectangle {}
public record Circle(double r) implements Shape {}
public record Rectangle(double w, double h) implements Shape {}

    JEP 409: Sealed Classes

  • LangSwitch expressions14

    No fall-through with ->; yield returns a value from a block. Enum switches are checked for exhaustiveness.

    int days = switch (month) {
    case FEBRUARY -> 28;
    case APRIL, JUNE, SEPTEMBER, NOVEMBER -> 30;
    default -> 31;
};

    JEP 361: Switch Expressions

  • LangText blocks15

    Multi-line strings; indentation is stripped relative to the closing delimiter. Great for SQL, JSON, HTML.

    String json = """
        { "name": "%s", "active": true }
        """.formatted(name);

    JEP 378: Text Blocks

  • LangPattern matching for instanceof16
    if (obj instanceof String s && s.length() > 3) { s.toUpperCase(); }

@Override public boolean equals(Object o) {
    return o instanceof Point p && x == p.x && y == p.y;
}

    JEP 394: Pattern Matching for instanceof

  • JVMHelpful NullPointerExceptions15

    The message names exactly what was null. Local variable names need -g.

    Cannot invoke "B.c()" because "a.b()" is null

    JEP 358: Helpful NullPointerExceptions

  • JVMZGC and Shenandoah production-ready15

    Low-pause concurrent collectors. ZGC is non-generational in 17 (generational arrives in 21). Shenandoah is not in every vendor build. G1 remains the right default for most services.

    java -XX:+UseZGC -jar app.jar

    JEP 377: ZGC: A Scalable Low-Latency Garbage Collector (Production)
    JEP 379: Shenandoah: A Low-Pause-Time Garbage Collector (Production)

  • JVMStrong encapsulation of JDK internals17

    --illegal-access is gone. This is where most 8→17 migrations hurt: upgrade libraries first, use --add-opens as a last resort.

    --add-opens java.base/java.lang=ALL-UNNAMED

    JEP 403: Strongly Encapsulate JDK Internals
    JEP 396: Strongly Encapsulate JDK Internals by Default

  • JVMClass data sharing (CDS)12–13

    JDK class archive is on by default. App-level archives help startup further.

    java -XX:ArchiveClassesAtExit=app.jsa -jar app.jar   # create
java -XX:SharedArchiveFile=app.jsa -jar app.jar      # use

    JEP 341: Default CDS Archives
    JEP 350: Dynamic CDS Archives

  • JVMG1 improvements12–14

    Abortable mixed collections and prompt memory return (12), NUMA-aware allocation (14).

    JEP 344: Abortable Mixed Collections for G1
    JEP 346: Promptly Return Unused Committed Memory from G1
    JEP 345: NUMA-Aware Memory Allocation for G1

  • JVMZGC improvements13–16

    Uncommits unused memory and supports 16 TB heaps (13), macOS/Windows (14–15), concurrent stack processing for sub-ms pauses (16).

    JEP 351: ZGC: Uncommit Unused Memory (Experimental)
    JEP 364: ZGC on macOS (Experimental)
    JEP 365: ZGC on Windows (Experimental)
    JEP 376: ZGC: Concurrent Thread-Stack Processing

  • JVMShenandoah GC12–15

    Experimental in 12, production in 15. Only in OpenJDK-based builds, not Oracle JDK.

    JEP 189: Shenandoah: A Low-Pause-Time Garbage Collector (Experimental)
    JEP 379: Shenandoah: A Low-Pause-Time Garbage Collector (Production)

  • JVMElastic metaspace16

    Class metadata memory is returned to the OS promptly and fragments less. Helps apps with heavy class loading/unloading (hot redeploys, many proxies).

    JEP 387: Elastic Metaspace

  • JVMJFR event streaming14

    Consume JFR events in-process, live, without dumping a file.

    try (var rs = new RecordingStream()) {
    rs.enable("jdk.CPULoad").withPeriod(Duration.ofSeconds(1));
    rs.onEvent("jdk.CPULoad", e -> System.out.println(e.getFloat("jvmUser")));
    rs.start();
}

    JEP 349: JFR Event Streaming

  • JVMjpackage16

    Builds native installers (msi, dmg, deb, rpm) with a bundled runtime.

    jpackage --name MyApp --input lib --main-jar app.jar --type deb

    JEP 392: Packaging Tool

  • JVMmacOS/AArch64 port (Apple Silicon)17

    Native JDK for Apple Silicon Macs, no Rosetta needed.

    JEP 391: macOS/AArch64 Port

  • JVMWindows/AArch64 port16

    Native JDK for Windows on ARM.

    JEP 388: Windows/AArch64 Port

  • LibUnix-domain sockets16
    var addr = UnixDomainSocketAddress.of("/tmp/app.sock");
try (var ch = SocketChannel.open(StandardProtocolFamily.UNIX)) { ch.connect(addr); }

    JEP 380: Unix-Domain Socket Channels

  • DeprecatedSecurity Manager deprecated for removal17

    Permanently disabled in 24, see Java 25.

    JEP 411: Deprecate the Security Manager for Removal

  • DeprecatedApplet API deprecated for removal17

    First deprecated in 9; now marked for removal.

    JEP 398: Deprecate the Applet API for Removal

  • DeprecatedBiased locking disabled by default15

    Deprecated and off by default in 15; removed in 18.

    JEP 374: Deprecate and Disable Biased Locking

  • RemovedCMS garbage collector14

    Deprecated in 9, removed in 14. G1, ZGC and Shenandoah are the concurrent options.

    JEP 363: Remove the Concurrent Mark Sweep (CMS) Garbage Collector

  • RemovedPack20014

    Pack200 compression tools and API removed.

    JEP 367: Remove the Pack200 Tools and API

  • RemovedNashorn JavaScript engine15

    Removed after deprecation in 11.

    JEP 372: Remove the Nashorn JavaScript Engine

  • RemovedRMI Activation17

    The RMI Activation mechanism is gone; the rest of RMI remains.

    JEP 407: Remove RMI Activation

  • RemovedExperimental AOT compiler (jaotc) and Graal JIT17

    The experimental ahead-of-time compiler and Graal JIT integration were removed.

    JEP 410: Remove the Experimental AOT and JIT Compiler

  • RemovedSolaris/SPARC ports17

    Solaris and SPARC support removed from the JDK.

    JEP 381: Remove the Solaris and SPARC Ports

Java 21 covers 18–21

Pattern matching completes data-oriented style; virtual threads change concurrent backends.

  • LangPattern matching for switch21

    Type patterns, guards and case null. Exhaustive over sealed types, so adding a subtype breaks the build where it matters.

    double area(Shape s) {
    return switch (s) {
        case Circle c    -> Math.PI * c.r() * c.r();
        case Rectangle r -> r.w() * r.h();
    };
}
case Integer i when i > 100 -> "big";

    JEP 441: Pattern Matching for switch

  • LangRecord patterns21

    Deconstruct records, nested, in instanceof and switch.

    if (obj instanceof Point(int x, int y)) { use(x + y); }
case Line(Point(var x1, var y1), Point(var x2, var y2)) -> Math.hypot(x2-x1, y2-y1);

    JEP 440: Record Patterns

  • JVMVirtual threads21

    Cheap JVM-scheduled threads: thread-per-request code with async-level scalability. Helps I/O-bound work only. Never pool them; limit concurrency with a Semaphore. Blocking in synchronized pins the carrier in 21 (fixed in 24).

    try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) ex.submit(() -> handle(i));
}
Thread.ofVirtual().name("worker-", 0).start(() -> doWork());

    JEP 444: Virtual Threads

  • JVMGenerational ZGC21

    Far lower CPU and memory overhead than non-generational ZGC. Default ZGC mode from 23; the old mode is removed in 24.

    java -XX:+UseZGC -XX:+ZGenerational -jar app.jar   # 21

    JEP 439: Generational ZGC

  • JVMUTF-8 by default18

    Ends "works on Linux, garbled on Windows". Explicit charsets are still better style. Legacy behavior: -Dfile.encoding=COMPAT.

    new FileReader(f, StandardCharsets.UTF_8);

    JEP 400: UTF-8 by Default

  • JVMSimple Web Server (jwebserver)18

    Minimal static file server for prototyping and testing; not for production.

    jwebserver -p 8000 -d /tmp/site

    JEP 408: Simple Web Server

  • JVMDynamic agent loading warning21

    Attaching agents at runtime (Mockito, ByteBuddy and similar) now prints a warning; a future release will disallow it by default. Prefer -javaagent, or opt in explicitly:

    -XX:+EnableDynamicAgentLoading

    JEP 451: Prepare to Disallow the Dynamic Loading of Agents

  • LibSequenced collections21

    Uniform first/last/reversed API for ordered collections. HashSet/HashMap are excluded. getFirst() on empty throws.

    list.getFirst();  list.getLast();  list.reversed();   // view
map.firstEntry(); map.putFirst("w", 0);

    JEP 431: Sequenced Collections

  • JavadocJavadoc {@snippet}18

    Compiler-checkable code samples in documentation, instead of <pre> blocks.

    /** {@snippet :
 *   var p = new Point(1, 2);   // highlighted and verified
 * } */

    JEP 413: Code Snippets in Java API Documentation

  • PreviewStructured concurrency21

    Preview in 21 (needs --enable-preview). The API changed since; see Java 25.

    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    var user  = scope.fork(() -> findUser(id));
    var order = scope.fork(() -> fetchOrder(id));
    scope.join().throwIfFailed();
}

    JEP 453: Structured Concurrency (Preview)

  • PreviewForeign Function & Memory API21

    Third preview in 21; became final in 22 (see Java 25).

    JEP 442: Foreign Function & Memory API (Third Preview)

  • PreviewScoped Values21

    Debuted as a preview in 21; final in 25 (see Java 25).

    JEP 446: Scoped Values (Preview)

  • DeprecatedFinalization deprecated for removal18

    Replace finalize() with try-with-resources or Cleaner. You can test without finalization:

    --finalization=disabled

    JEP 421: Deprecate Finalization for Removal

  • RemovedBiased locking18

    Removed; disabled by default since 15.

    JEP 374: Deprecate and Disable Biased Locking

  • RemovedThread.stop()20

    Now throws UnsupportedOperationException.

Java 25 covers 22–25

Polish plus real runtime wins (object headers, AOT cache) and the FFM API.

  • LangCompact source files, instance main25

    No class, no static, no String[] args. New IO class for console I/O. Good for scripts, not for real applications.

    void main() {
    var name = IO.readln("Name: ");
    IO.println("Hi " + name);
}

    JEP 512: Compact Source Files and Instance Main Methods

  • LangModule import declarations25

    Import everything a module exports. Ambiguities (java.util.Date vs java.sql.Date) need a single-type import.

    import module java.base;
import module java.sql;

    JEP 511: Module Import Declarations

  • LangFlexible constructor bodies25

    Validate and compute before super(...), as long as you don't touch this.

    Square(double side) {
    if (side <= 0) throw new IllegalArgumentException();
    super(side * side);
}

    JEP 513: Flexible Constructor Bodies

  • LangUnnamed variables and patterns _22
    catch (NumberFormatException _) { return false; }
case Rectangle(Point(var x, _), _) -> use(x);

    JEP 456: Unnamed Variables & Patterns

  • JVMMulti-file source launch22

    Sources in the same tree are compiled in memory. Libraries still go on -cp.

    java Main.java     # Helper.java next to it is picked up

    JEP 458: Launch Multi-File Source-Code Programs

  • JVMCompact object headers25

    Header shrinks from 12–16 bytes to 8 bytes: smaller heap, often less GC work. Product feature in 25 but off by default (on by default from 27, see Java 29); test with your workload.

    java -XX:+UseCompactObjectHeaders -jar app.jar

    JEP 519: Compact Object Headers
    JEP 450: Compact Object Headers (Experimental)

  • JVMAOT cache (Project Leyden)24–25

    Pre-parsed, pre-linked classes plus method profiles: faster startup and warmup, builds on CDS. Must match the same JVM and class path; create it at build time.

    java -XX:AOTCacheOutput=app.aot -jar app.jar   # training run
java -XX:AOTCache=app.aot -jar app.jar         # production

    JEP 483: Ahead-of-Time Class Loading & Linking
    JEP 514: Ahead-of-Time Command-Line Ergonomics
    JEP 515: Ahead-of-Time Method Profiling

  • JVMsynchronized no longer pins virtual threads24

    Removes the biggest virtual-thread caveat of 21; no need to rewrite to ReentrantLock. Remaining pinning: native frames, some class-init blocking.

    synchronized (lock) { blockingCall(); }   // 24+: virtual thread unmounts

    JEP 491: Synchronize Virtual Threads without Pinning

  • JVMGenerational Shenandoah25

    Same idea as generational ZGC. Not in Oracle JDK; Temurin and Red Hat builds include it.

    java -XX:+UseShenandoahGC -XX:ShenandoahGCMode=generational -jar app.jar

    JEP 521: Generational Shenandoah

  • JVMWhich GC in 25?22–25

    G1 (default): balanced, fine for most services. Parallel: batch throughput. Serial: tiny heaps. ZGC: now generational only (non-generational removed in 24): low tail latency on large heaps. Shenandoah: optional generational mode, not in Oracle JDK. Epsilon: benchmarks only. Rule of thumb: stay on G1 until tail latency or heap size proves a problem.

    JEP 474: ZGC: Generational Mode by Default
    JEP 490: ZGC: Remove the Non-Generational Mode
    JEP 521: Generational Shenandoah

  • JVMJFR CPU-time profiling25

    Experimental, Linux only: samples by CPU time instead of wall-clock time.

    JEP 509: JFR CPU-Time Profiling (Experimental)

  • JVMJFR cooperative sampling25

    Stack sampling at safepoints, which makes sampling safer and more stable.

    JEP 518: JFR Cooperative Sampling

  • JVMJFR method timing and tracing25

    New events measure execution time and trace calls of chosen methods.

    JEP 520: JFR Method Timing & Tracing

  • LibForeign Function & Memory API22

    Replaces JNI and most Unsafe off-heap code. Run with --enable-native-access=ALL-UNNAMED; jextract generates bindings.

    Linker linker = Linker.nativeLinker();
MethodHandle strlen = linker.downcallHandle(
    linker.defaultLookup().find("strlen").orElseThrow(),
    FunctionDescriptor.of(ValueLayout.JAVA_LONG, ValueLayout.ADDRESS));
try (Arena arena = Arena.ofConfined()) {
    long len = (long) strlen.invokeExact(arena.allocateFrom("Hello"));
}

    JEP 454: Foreign Function & Memory API

  • LibStream Gatherers24

    Custom intermediate stream operations (collectors are custom terminal ones).

    stream.gather(Gatherers.windowFixed(3)).toList();   // [[1,2,3],[4,5,6],[7]]
stream.gather(Gatherers.windowSliding(2)).toList();
urls.stream().gather(Gatherers.mapConcurrent(10, this::fetch)).toList();

    JEP 485: Stream Gatherers

  • LibClass-File API24

    Standard bytecode read/write/transform (java.lang.classfile), tracks every JDK release unlike ASM. Mostly relevant to framework and tooling authors.

    ClassModel cm = ClassFile.of().parse(Path.of("Foo.class"));
cm.methods().forEach(m -> System.out.println(m.methodName().stringValue()));

    JEP 484: Class-File API

  • LibScoped Values25

    Immutable, bounded-lifetime alternative to ThreadLocal; cheap with virtual threads. Use for request context, principals, trace IDs.

    static final ScopedValue<User> CURRENT_USER = ScopedValue.newInstance();
ScopedValue.where(CURRENT_USER, authenticate(req)).run(() -> service.process());
CURRENT_USER.get();   // anywhere deeper in the call tree

    JEP 506: Scoped Values

  • LibVector API (still incubating)16–25

    Portable SIMD, now in its tenth incubation round, waiting on Project Valhalla. Usable but not stable.

    --add-modules jdk.incubator.vector

    JEP 508: Vector API (Tenth Incubator)

  • LibPost-quantum crypto: ML-KEM and ML-DSA24

    ML-KEM (key encapsulation) and ML-DSA (signatures) arrived in 24.

    JEP 496: Quantum-Resistant Module-Lattice-Based Key Encapsulation Mechanism
    JEP 497: Quantum-Resistant Module-Lattice-Based Digital Signature Algorithm

  • LibKey Derivation Function API25

    Standard API for key derivation functions such as HKDF; final in 25.

    JEP 510: Key Derivation Function API

  • JavadocMarkdown in Javadoc23
    /// Returns the **sum** of two numbers.
///
/// - `a` first value
/// - `b` second value
int add(int a, int b) { return a + b; }

    JEP 467: Markdown Documentation Comments

  • PreviewStructured concurrency (new API shape)25

    Need --enable-preview; classes compiled this way only run on the exact same Java version. Don't ship against previews.

    try (var scope = StructuredTaskScope.open()) {
    var user  = scope.fork(() -> findUser(id));
    var order = scope.fork(() -> fetchOrder(id));
    scope.join();
}

    JEP 505: Structured Concurrency (Fifth Preview)

  • PreviewStable Values25

    Lazily initialized, then immutable; the JVM can optimize them like constants.

    Supplier<Logger> logger = StableValue.supplier(() -> Logger.create("app"));

    JEP 502: Stable Values (Preview)

  • PreviewPrimitive patterns in switch25

    Patterns and instanceof work with primitive types.

    switch (x) { case int i when i < 0 -> "negative"; case int i -> "positive"; }

    JEP 507: Primitive Types in Patterns, instanceof, and switch (Third Preview)

  • Deprecatedsun.misc.Unsafe memory access: warnings23–24

    Memory-access methods are deprecated for removal (23) and warn on first use (24). Libraries like Netty and Kryo are migrating to VarHandle and FFM. Check your dependencies when upgrading.

    --sun-misc-unsafe-memory-access=allow|warn|debug|deny

    JEP 471: Deprecate the Memory-Access Methods in sun.misc.Unsafe for Removal
    JEP 498: Warn upon Use of Memory-Access Methods in sun.misc.Unsafe

  • DeprecatedJNI and native access warnings24

    Using JNI or FFM now warns unless native access is enabled for the module; it will become stricter later.

    --enable-native-access=ALL-UNNAMED

    JEP 472: Prepare to Restrict the Use of JNI

  • RemovedSecurity Manager permanently disabled24

    System.setSecurityManager now always throws. No replacement inside the JVM; use container or OS-level sandboxing.

    JEP 486: Permanently Disable the Security Manager

  • RemovedString Templates dropped23

    Previewed in 21 and 22, removed in 23 pending a redesign. Don't build on them.

    JEP 430: String Templates (Preview)
    JEP 459: String Templates (Second Preview)

  • RemovedWindows 32-bit x86 port24

    Deprecated for removal in 21, removed in 24.

    JEP 479: Remove the Windows 32-bit x86 Port

  • RemovedLinux 32-bit x86 port25

    Removed in 25.

    JEP 503: Remove the 32-bit x86 Port

Java 29 covers 26–29 Unreleased

So far mostly runtime changes: G1 and compact headers by default, structured concurrency going final. Value classes are the big preview, and there are no final language features yet.

Unreleased — work in progress. Java 29 is the next LTS, planned for September 2027, and does not exist yet. This section collects what is already known on the way there. Java 26 (March 2026) and Java 27 (September 2026) are released, so their items are final and worth adopting now. Java 28 (March 2027) is in development: its items reflect JEP status as of 18 October 2026 and can still change. Java 29 has no targeted JEPs yet. Keep adding features here as each release ships.
  • JVMG1 is the default GC everywhere27

    Before 27 the JVM silently picked Serial GC on machines with under 2 CPUs or about 1.8 GB RAM, so small containers ran a different collector than your laptop. From 27, G1 is chosen in all environments. Re-check GC flags and heap sizing for tiny containers.

    -XX:+UseSerialGC   # still available explicitly

    JEP 523: Make G1 the Default Garbage Collector in All Environments

  • JVMCompact object headers on by default27

    Shipped as an opt-in product feature in 25; on by default from 27. Object headers shrink from 96 to 64 bits on 64-bit platforms. Opt out if a native agent or tool assumes the old layout.

    -XX:-UseCompactObjectHeaders

    JEP 534: Compact Object Headers by Default
